Alcance  del  Plan  de  Pruebas  
 
Este  plan  contempla  la  validación  de  las  siguientes  áreas:  
1.1  Aplicación  Móvil  (Ionic/Angular)  
●  Autenticación  de  usuarios  (donantes  con  RUT  y  representantes  con  correo).  ●  Registro  de  donantes  con  validación  de  datos.  ●  Generación  y  escaneo  de  códigos  QR  para  registrar  donaciones.  ●  Visualización  de  centros  de  donación  geolocalizados  (con  Mapbox).  ●  Solicitudes  de  donación  y  registro  de  historial.  ●  Chatbot  de  ayuda  integrado  para  asistencia  inmediata.

1.2  Plataforma  Web  (Django)  
●  Autenticación  de  representantes  y  administradores.  ●  Gestión  de  campañas  de  donación  y  registro  de  datos.  ●  Acceso  a  información  centralizada  desde  el  backend.  ●  Panel  de  control  para  administración  de  usuarios  y  campañas.  
 
1.3  Análisis  de  Datos  (Apache  Superset)  
●  Visualización  de  indicadores  de  rendimiento  de  campañas.  ●  Paneles  interactivos  para  la  toma  de  decisiones.  ●  Despliegue  en  la  nube  con  Render  para  acceso  seguro.  
 
Objetivos  del  Plan  de  Pruebas  
 
●  Validar  el  comportamiento  correcto  del  sistema  frente  a  entradas  válidas  e  inválidas.  ●  Comprobar  la  integridad  de  los  datos  enviados  entre  frontend  y  backend.  ●  Verificar  la  interacción  entre  módulos  (QR,  mapas,  formularios,  chatbot).  ●  Identificar  errores  funcionales  y  de  interfaz.  ●  Garantizar  una  experiencia  fluida  para  los  distintos  perfiles  de  usuario.

Matriz  de  riesgo  
Riesgo  Fase  Probabilidad  
Impacto  Acción  de  mitigación  
Falta  de  dominio  en  openRouter  
Desarrollo  (Chatbot)  
Alta  Medio  Capacitación  rápida  con  tutoriales  oficiales  +  asignar  un  miembro  del  equipo  como  responsable  de  esta  integración.  
Dificultad  con  Apache  Superset  
Análisis  de  datos  
Media  Alto  
Usar  alternativas  temporales  (como  Power  BI)  o  contar  con  apoyo  externo  (mentor/capacitación  express).  
Geolocalización  imprecisa  
Desarrollo  (Mapas)  
Media  Alto  
Validar  datos  con  APIs  confiables  (como  Google  Maps)  y  realizar  pruebas  de  campo  con  usuarios  reales.  
Baja  adaptación  del  Chatbot  
Post-lanzamiento  
Media  Bajo  
Ajustes  iterativos  en  el  desarrollo,  priorizando  preguntas  frecuentes  según  retroalimentación  de  usuarios.  
Problemas  de  escalabilidad  en  BD  
Desarrollo  Baja  Alto  
Diseñar  un  esquema  optimizado  en  PostgreSQL  y  realizar  pruebas  de  carga  desde  etapas  tempranas.  
Fallos  en  notificaciones/alertas  
Desarrollo  Alta  Medio  
Utilizar  servicios  confiables  de  notificaciones  (ej:  Firebase)  y  testear  en  múltiples  dispositivos  y  sistemas  operativos.  
Baja  participación  o  interés  en  gamificación  
QA  Media  Medio  
Evaluar  incentivos  más  atractivos  (además  de  insignias),  y  explorar  alianzas  con  influencers  o  campañas  externas.  
Retrasos  en  integración  de  RRSS  
Desarrollo  Baja  Bajo  
Utilizar  SDKs  oficiales  (Facebook  API,  Twitter  API)  y  designar  un  desarrollador  específico  para  esta  funcionalidad.  
Datos  inconsistentes  en  registro  
Desarrollo  Media  Alto  
Validación  estricta  en  frontend  y  backend  +  pruebas  unitarias  en  formularios  con  Jasmine.  
Falta  de  experiencia  con  organizaciones  de  salud  
Planificación  Baja  Alto  
Coordinar  reuniones  tempranas  con  stakeholders  clave  (como  Cruz  Roja)  para  alinear  requisitos  y  objetivos  del  sistema.
